# FloodGuard Open-Meteo source-check helper

This helper makes one real HTTP request to the same Open-Meteo Forecast API endpoint and uses the same parameter choices as FloodGuard's adapter. It records a pass, incomplete response, or failure honestly; it does not mark a failed request as verified.

## Install into the repository

Copy `backend/check_open_meteo_source.py` from this package into the existing FloodGuard repository's `backend` folder. Do not copy the package's outer folder into the repository.

Run from the FloodGuard repository root in PowerShell, with the project's environment active:

```powershell
python backend\check_open_meteo_source.py
```

If needed, run with the backend virtual environment directly:

```powershell
.\backend\.venv\Scripts\python.exe backend\check_open_meteo_source.py
```

The project needs `httpx` installed (the existing Open-Meteo adapter already uses it). The command makes a network request and may fail when there is no internet, DNS, or provider access. A failure is still recorded and must be described as failed/incomplete, not verified.

## Files generated by the script

- `docs/OPEN_METEO_SOURCE_CHECK.md` — readable, timestamped report.
- `data/reference/open_meteo_source_check.json` — machine-readable metadata, including every returned forecast valid time.
- `docs/DATA_SOURCES.md` — the script updates the Open-Meteo decision and inserts/replaces a source-check record.

The one test location is the representative point 19.0760, 72.8777. This only checks the endpoint and response format for one point; it does not establish ward-level coverage, validate forecast skill, or prove flooding. Usage-term links and review date are included in the report; review them again before deployment.
